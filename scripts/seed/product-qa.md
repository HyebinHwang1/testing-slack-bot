## 상품

### Q: 상품 엑셀 업로드는 어떻게 동작하고 어떤 검증에서 실패하나요?
상품 엑셀 업로드는 `파일 첨부 → 엑셀 파싱(동기) → 검증·벌크 처리(비동기 Celery) → JobResult 저장` 순으로 동작한다. 업로드가 막히는 지점을 단계별로 정리한다.

- **API**: `PATCH /adminapi/v1/admin/product/update_or_create_by_excel/`
- **샘플 양식**: `GET /adminapi/v1/admin/product/download_create_sample_excel/`
- **시리얼라이저**: `ProductExcelSerializer`(BO) / `PoProductExcelSerializer`(PO)

**먼저 알아야 할 핵심 규칙 3가지**

1. **생성·업데이트는 `code` 컬럼으로 자동 분기된다.** 전 행 빈값이면 전체 생성, 전 행 값 있으면 전체 업데이트. **일부만 채운 혼합은 에러**다.
2. **헤더 1~5줄을 삭제하면 안 된다.** 상단 행이 빠지면 파싱에서 즉시 실패한다.
3. **가격 필수 여부는 계약형태(CP/1P/3P)마다 다르다.** (5단계 표 참조)

**1단계 · 파일 구조 검증 (파싱, 동기)**

| 항목 | 에러 메시지 |
| --- | --- |
| 헤더 행 삭제 | "1~5줄까지 삭제하지 않고…" |
| 알 수 없는 컬럼 | "알 수 없는 컬럼이 포함되어 있습니다: {컬럼명}" |
| 필수 컬럼 누락 | "엑셀 파일에서 다음 컬럼을 찾을 수 없습니다: {컬럼명}" |
| 데이터 행 없음 | "데이터가 없습니다." |
| 파일 미첨부 | "엑셀 파일을 첨부해주세요." |
| 작업 중복 | "엑셀 업로드 작업이 이미 진행중입니다." |

**2단계 · 필수 필드**

| 필드 | 필수 조건 | 제약 |
| --- | --- | --- |
| 상품명(`name`) | 항상 | 최대 200자 |
| 영문상품명(`english_name`) | 항상 | 최대 200자 |
| 공급사 상품명(`supply_name`) | 항상 | 최대 200자 |
| 샵 ID(`seller`) | 항상 | 존재하는 샵 + 담당 부서 필요 |
| 원산지(`origin`) | 한국 파트너만 | 등록된 원산지 코드 |
| 옵션입력(`option_set`) | 생성 시만 | 형식 규칙 준수 |

**3단계 · 형식이 엄격한 필드** (틀리면 행 단위 실패)

- **`option_set`**: `옵션그룹명{값1|값2}//그룹2{값1|값2}` (예: `color{red #E90606|blue #0000FF}//size{s|m|l}`). `//`로 그룹, `|`로 값 구분. 동일 (옵션명,값) 중복 불가. 옵션명은 영문 소문자로 자동 정규화. 색상 헥스코드·`[model]` 태그 지원.
- **`category_set`**: `65` 또는 `65|66|67`. 앞뒤·연속 파이프(`|65`, `65|`, `65||66`)·숫자 아닌 값·없는 ID 불가. 상위 카테고리는 자동 포함.
- **`highlight_text`**: `문구1,문구2`. 앞뒤·연속 콤마 불가. 각 항목 2~12자, 전체 합산 제한 있음.
- **`image`/`image_set`**: 유효 URL·200자 이하. 공백은 `%20` 자동 변환, `image_set`은 `|`로 구분. (옵션 활성 시 실제 접근 가능 여부까지 검증)
- **`display`/`selling`/`released`**: `Y`(현재 시각 활성) · `N`/빈칸(비활성) · `2025-06-01 09:00:00`(지정 시각 활성). 이 외 값은 에러.

**4단계 · 값이 들어가면 안 되는 케이스**

- **`supply_name`** — CP 계약이면 공급사 상품명 중간 공백 불가 (`상품A B` ✗ / `상품AB` ✓).
- **`custom_code`** — `(seller, custom_code)` 조합 중복 불가. 다른 상품이 쓰는 코드·엑셀 내 중복 모두 불가.

**5단계 · 가격 필드 (계약형태별 필수 여부)**

| 계약형태 | 판매가 | 공급가 | 소매가 | 수수료율 |
| --- | --- | --- | --- | --- |
| CP | 자동계산 | **필수**(원화) | **필수**(원화) | - |
| 1P 직매입 | 자동계산 | 자동계산 | **필수**(원화) | **필수** |
| 3P 특약매입 | 자동계산 | 자동계산 | **필수**(원화/엔화) | - |
| 3P 위탁 | **필수**(엔화) | 자동계산 | **필수**(원화/엔화) | - |

값은 숫자 문자열이어야 하며(변환 불가 시 에러), 소수점은 버림 처리한다.

**6단계 · 참조 필드 (DB에 존재해야 함)**

`seller`(활성 샵 slug), `manufacturer`(활성 제조사 코드), `hscode`(등록 HS코드), `md_staff`·`web_staff`(활성 스태프 이메일), `origin`(원산지 코드), `category_set`(카테고리 ID).

**읽기 전용 필드 (입력해도 무시)**

`seller_name`, `사이즈`, `색상`, `현재할인율`, `품목명`, `MD승인상태`, `승인요청유형`, `반려사유영역`, `승인반려사유`.

**업데이트 시 추가 제약**

- MD 승인 대기 중인 상품은 특정 필드만 수정 가능하다.
- 가격 변경 시 품목 가격이 자동 재계산된다 (CP-J: 공급가·판매가 / CP-K: 공급가 인상 / 1P: 판매가·수수료율).

**PO 시리얼라이저 차이 (`PoProductExcelSerializer`)**

- 입력 불가 필드: `md_staff`, `web_staff`, `supply_name_cn`, `title`, `highlight_text`
- 업데이트 시 `seller` 변경 불가 · 가격은 항상 자동계산

**에러 응답**

실패 시 `JobResult.info`에 행별 에러 JSON이 저장되며, 필드명은 한글로 매핑돼 노출된다.

```json
[{"상품명": ["이 필드는 필수 항목입니다."], "non_field_errors": ["상품 코드를 생성할 땐 빈 칸으로, 수정할 땐 필수입니다."]}]
```
