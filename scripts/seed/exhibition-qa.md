## 전시

### Q: 전시개편 3차는 왜 진행하며 무엇을 목표로 하나요?
전시개편 3차는 사업 모델이 '한국 디자이너 브랜드 중개'에서 **'디렉터(인플루언서) 사업' 중심**으로 전환되면서 추진한 전시 체계 개편이다. 단순 상품 나열을 넘어 디렉터의 인물 포커싱으로 샵 단위 큐레이션을 강화하고, 브랜드 아이덴티티를 고객에게 직관적으로 보여주는 것이 목적이다.

**전환 배경**

- **인물 중심 큐레이션 강화**: 디렉터가 고른 상품의 위계를 재정립해 '인플루언서 기반 샵'의 특수성을 극대화한다.
- **UI/UX 체계 전환**: 고화질 세로형 이미지 중심에서 **정방형 디렉터 이미지 중심**으로 바꾼다. 저화질 디렉터 이미지를 써서 리소스 소모와 로딩 시간을 줄이고, 이탈률을 낮춰 구매 전환 접근성을 높인다.

**3대 핵심 과제**

1. **정보 가독성 향상**: PLP(상품 목록 페이지)의 정보 과부하를 해소하고 핵심 카테고리·셀링 포인트를 우선 노출한다.
2. **PB 브랜드 인지도 강화**: 오리지널 전용 UI와 뱃지 시스템으로 자사 브랜드의 시각적 위계를 확보한다.
3. **물류 효율화·비용 개선**: 무료배송 허들을 올리고 배송 지연 보상을 자동화해 운영 리스크를 관리하고 물류 수익 구조를 최적화한다.

### Q: PLP에서 상품명 대신 카테고리명은 어떤 규칙으로 노출되나요?
PLP의 정보 밀도를 낮추고 스캔 피로도를 줄이기 위해, 긴 상품명 대신 **최하위(Leaf) 카테고리명**을 노출하는 '상품명 대체 로직'을 적용한다. 고객이 상품의 본질을 즉시 파악하도록 돕는 것이 목적이다.

**기본 원칙**

전체 상품명 대신, 상품이 속한 최하위(Leaf) 카테고리명을 노출한다.

**적용 구좌 (17개)**

메인홈 전체(최근본·기획전 연결·blux 추천·카테고리별 랭킹), 메인홈 랭킹탭·신작탭·여성탭·남성탭, 기획전 상세, 카테고리 상품목록, GNB 좋아요 목록, 스타일 컨텐츠 연결상품, PDP 하단 추천(blux·샵·카테고리), 통합검색 상품탭, 마이페이지 최근본, 샵상세 기획전·BEST·Original·하단 상품목록, 메인홈 기획전 연결 목록.

**미적용 구좌 (4개)**

결제 여정과 직결된 **카트, 상품상세 본문, 주문서, 마이페이지 주문상세**는 정보 명확성을 위해 기존 상품명을 유지한다.

**노출 범위와 예외**

- **범위 제한**: 1~3depth '전체' 페이지까지만 카테고리명을 노출한다. 3depth 최하위 카테고리 페이지 내부에서는 텍스트를 미노출한다.
- **예외**: '잠옷'·'세트'는 3depth가 없으므로 전용 페이지에서 텍스트를 노출하지 않는다.
- **기타 카테고리**: '기타(3depth)'에만 매핑된 상품은 상위 뎁스명을 끌어오지 않고 '기타'로 노출한다(데이터 정합성용 Spec-out).

**해상도별 노출 정책** (텍스트 2행 초과 시 말줄임표 처리)

| 필드 | 일반 뷰 (125x156) | 가로 스크롤 뷰 (108x135) |
| --- | --- | --- |
| 카테고리명 | 노출 | 노출 |
| 상품 강조문구 | 노출 | 미노출 |
| 판매 상태문구 | 노출 | 미노출 |

**MD 입력 문구 파싱 규칙** ('상품 강조문구'·'판매 상태문구', 최대 12자·공백 불가)

- **PLP**: 입력 형태 유지 (예: `6회재판매,4color`)
- **PDP**: 콤마 기준 분리 후 대괄호 처리 (예: `[6회재판매][4color]`)

### Q: 상품 뱃지는 어떤 우선순위와 규칙으로 노출되나요?
뱃지 시스템은 고객의 의사결정 속도를 높이고 플랫폼 신뢰도를 결정하는 핵심 장치다. 우선순위에 따라 자동 노출되며, 중복·충돌은 상호배제 규칙으로 제거한다.

**우선순위 체계** (높음 → 낮음)

1. **품절** (판매 불가)
2. **쿠폰** (즉시 혜택)
3. **발매예정** (入荷予定)
4. **무료배송** (수동 운영)
5. **브랜드배송** (출고처 정보)
6. **구매제한** (기존 '수량한정'에서 명칭 변경)

**노출 개수 제약**

- PLP: 상위 2개까지
- PDP: 상위 5개까지

시각적 과부하를 막기 위한 제한이다.

**상호배제·중복 제거 로직**

- **품절 상호배제**: '품절' 뱃지 적용 시, 혼선을 막기 위해 하단 텍스트 뱃지 전체를 강제 미노출한다.
- **즉일발송 중복 제거**: 썸네일에 '즉일발송' 아이콘이 노출되면, 하단 '브랜드배송' 뱃지는 중복으로 보고 강제 해제한다.
- **오리지널 UI 독립성**: 썸네일 우측 상단 '오리지널 아이콘'은 하단 뱃지와 독립적으로 작동한다. 품절이 되어도 아이콘을 유지해 PB 브랜드 가치를 계속 노출한다.

**신규 뱃지 '발매예정'**

'진열함/판매함' 상태이나 판매 일정이 미래인 경우 자동 적용되며, PDP의 CTA 버튼과 연동해 판매 예정 일자를 노출한다.

### Q: 다중 매핑된 상품의 대표 카테고리는 어떻게 정해지나요? (priority_key)
한 상품이 여러 카테고리에 매핑됐을 때 대표 카테고리를 정하기 위해 **priority_key 정렬 알고리즘**을 쓴다. 트리 정렬을 정수 비교 한 번으로 끝내 시스템 부하를 최소화하는 것이 핵심이다.

**인코딩 구조 (12자리 정수)**

트리 구조를 `(d1, d2, d3, d4)` 4개 슬롯으로 나누고, 각 슬롯을 3자리 정수로 인코딩한다.

**기술적 이점**

전위 순회(Preorder Traversal)를 보장하도록 설계해, 단순 정수 비교만으로 트리의 정렬 순서를 판단한다. 별도 트리 탐색 없이 정렬이 끝난다.

**그룹별 랭크 할당**

- **LEADING (RESERVED)**: 'SET'은 1~9순위를 선점해 같은 뎁스 안에서 절대 우위를 가진다.
- **일반**: 관리자가 설정한 순서(seq)에 따라 10~990 범위를 순차 할당받는다.
- **TRAILING**: 'UNISEX', 'ORIGINAL'은 991~999에 고정돼 항상 후순위에 배치된다.

**동기화와 스펙아웃**

- **실시간 동기화**: 카테고리 CUD가 발생하면 트랜잭션 커밋 후 Redis(`cache:category_priority:map`)를 통해 검색 인덱서(nova-search)와 동기화해 멱등성을 확보한다.
- **스펙아웃**: '기타(3depth)' 매핑 시 상위 뎁스명을 강제 호출하던 로직은 완전히 폐지했다.

### Q: 전시개편 3차에서 배송 정책과 지연 보상은 어떻게 바뀌나요?
물류비 개선과 수익 최적화를 위해 무료배송 기준을 올리고, 배송 프로세스를 투명화하며 지연 보상을 자동화한다.

**배송비 정책**

- 무료배송 기준: **6,000엔 → 10,000엔** 상향
- 기본 배송비: 550엔 유지

**배송 유형과 주문 분리**

- 창고 위치에 따라 **특급발송(일본창고)**과 **일반배송(한국 김포창고)**으로 유형을 엄격히 분리한다.
- 한 주문서에는 **단일 배송유형만** 허용한다. 장바구니에서 유형별로 상품을 그룹핑하고, 혼합 주문이면 주문서를 자동 분리 생성한다.

**배송 지연 자동 보상** (결제 완료일 기준 D+n, Daily Job 스케줄러)

| 기준 | 보상·조치 | 유효기간 |
| --- | --- | --- |
| D+7 | 부분 발송 지원 + 안내 메일 (보상금 없음) | - |
| D+14 | 200엔 포인트 지급 + 단순 변심 취소 허용 | 90일 |
| D+21 | 100엔 포인트 추가 지급 | 90일 |
| D+28 | 100엔 포인트 추가 지급 | 90일 |

**재고·품절 보상**

- 결제 후 14일 이상 입고되지 않는 품목은 **일시 품절**로 자동 전환해 추가 CS를 예방한다.
- 품절 취소 보상은 물류비 개선 차원에서 **1,000엔 쿠폰 → 300엔**으로 하향한다.

### Q: 전시개편 3차로 어드민에 추가·변경된 기능은 무엇인가요?
전시개편 3차 정책을 운영에서 지원하기 위해 어드민(백오피스)에 다음 기능을 추가·변경한다.

**상품 관리**

상품 조회/일괄 수정/엑셀 업로드에 **'상품 강조문구' 필드**를 신설하고, 기존 문구를 **'판매 상태문구'**로 명칭 변경한다.

**카테고리 관리**

- **'리프 카테고리 여부' 플래그** 추가
- PLP 텍스트 노출 제어용 **'상품목록 상품명 숨기기' 설정** 추가

**주문·보상 관리**

배송 지연 대상 필터링, 자동 보상 지급 로그 조회, D+14 이후 취소 정책 지원을 위한 UI를 확장한다.

### Q: 전시개편 3차 개발·배포 일정은 어떻게 되나요?
전시개편 3차는 BE → FE → QA를 거쳐 **5/27(수) 운영 서버 배포**를 목표로 한다.

| 단계 | 일정 | 핵심 Task |
| --- | --- | --- |
| BE 개발 | 04/30 ~ 05/08 | priority_key 연동, 보상 스케줄러, delivery_type 기반 주문 분리 |
| FE 개발 | 05/11 ~ 05/15 | PLP/PDP UI 최적화, 장바구니 배송 유형별 그룹핑 |
| QA 기간 | 05/21 ~ 05/26 | 17개 구좌 노출 로직 및 배송·보상 정합성 검증 |
| 배포 예정 | 05/27 (수) | 전체 시스템 운영 서버 배포 |
